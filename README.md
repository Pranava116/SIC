# TWIN-GUARD Simple UI

This version removes the Raspberry Pi requirement.

Architecture:

ESP32 → HiveMQ Cloud MQTT → Node.js backend → SQLite + Web UI

## 1. Install Node.js

Install a current LTS version of Node.js on the PC.

## 2. Configure MQTT

In this folder:

```text
.env.example
```

copy it to:

```text
.env
```

Then put your HiveMQ password in `.env`.

Do not upload `.env` to GitHub.

## 3. Install dependencies

Open Command Prompt / PowerShell in this folder:

```bash
npm install
```

## 4. Start

```bash
npm start
```

Open:

```text
http://localhost:3000
```

## What it displays

Actual ESP32 telemetry:
- RPM
- LM35 temperature
- vibration analog percentage
- vibration digital status
- motor state
- relay state
- MQTT connectivity

Estimated/decision information:
- thermal risk
- mechanical risk
- overall risk / health
- emergency interpretation

SQLite is created automatically at:

```text
data/twin_guard.db
```

No separate database server is required.

## MQTT commands

The dashboard publishes these commands to:

```text
machine01/command
```

- START
- STOP
- EMERGENCY_STOP
- RESET_EMERGENCY

Telemetry is read from:

```text
machine01/telemetry
```

## Important note about emergency reason

The current ESP32 telemetry in the supplied firmware does not contain an `emergencyReason` JSON field. Therefore this dashboard infers the reason from the fields that are currently available. For the final version, we can add one small field to the ESP32 so the dashboard shows the exact reason generated by the controller.
